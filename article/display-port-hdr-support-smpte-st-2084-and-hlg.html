DisplayPort HDR Support: SMPTE ST 2084 and HLG

This article explains how the VESA DisplayPort interface transmits and manages high-dynamic-range (HDR) Electro-Optical Transfer Functions (EOTFs), specifically SMPTE ST 2084 (Perceptual Quantizer) and Hybrid Log-Gamma (HLG). It covers the protocol architecture, metadata transport mechanisms via Secondary Data Packets, hardware handshake procedures via EDID/DisplayID, and the pixel pipeline requirements necessary to display accurate HDR video.

Bandwidth and Deep Color Architecture

Traditional standard-dynamic-range (SDR) video utilizes an 8-bit color depth and a standard gamma curve (such as BT.1886 or sRGB). Both SMPTE ST 2084 (PQ) and HLG require a minimum of 10-bit—and ideally 12-bit—color depth to prevent visible quantization artifacts (banding) across the wider dynamic range and the BT.2020 wide color gamut.

DisplayPort accommodated these requirements starting primarily with the DisplayPort 1.4 specification (and expanded in DisplayPort 2.0/2.1). By utilizing High Bit Rate 3 (HBR3) link rates and Display Stream Compression (DSC 1.2a), DisplayPort provides the throughput required to carry uncompressed or visually lossless 10-bit and 12-bit RGB or YCbCr 4:4:4 signals at high resolutions and refresh rates.

Secondary Data Packets (SDP) and CTA-861 InfoFrames

The physical interface alone does not interpret EOTF curves; instead, DisplayPort uses protocol-level data structures to signal the display on how to decode luminance and chrominance values. DisplayPort achieves this by encapsulating Consumer Technology Association (CTA-861) standard InfoFrames inside DisplayPort Secondary Data Packets (SDP).

During active video transmission, the graphics processing unit (GPU) inserts Dynamic Range and Mastering InfoFrames into the DisplayPort blanking intervals. The InfoFrame explicitly defines the EOTF identifier:

  • SMPTE ST 2084: Designated by a specific EOTF code byte in the InfoFrame, signaling the display to engage the non-linear PQ curve to interpret absolute luminance values up to 10,000 cd/m² (nits).
  • HLG: Designated by an alternative EOTF code byte, signaling the display to apply a hybrid transfer function that acts as a standard gamma curve in the lower luminance range and transitions to a logarithmic curve for highlights.

Static and Dynamic Metadata Transport

Handling different HDR EOTFs requires distinct metadata strategies, which DisplayPort routes through dedicated SDP fields:

  1. SMPTE ST 2084 (PQ / HDR10): Because PQ is an absolute luminance curve, the sink device needs context regarding the source's mastered boundaries to execute tone mapping correctly. DisplayPort transports static metadata conformant to SMPTE ST 2086 via the Dynamic Range and Mastering InfoFrame. This includes mastering display chromaticity coordinates, white point, and peak/minimum luminance values, alongside content metrics like Maximum Content Light Level (MaxCLL) and Maximum Frame-Average Light Level (MaxFALL).
  2. Dynamic Metadata (SMPTE ST 2094): DisplayPort 1.4a and later standards support extended Secondary Data Packets capable of transmitting frame-by-frame or scene-by-scene dynamic metadata for formats such as HDR10+ and Dolby Vision.
  3. HLG: HLG is designed as a relative, scene-referred system rather than an absolute luminance mapping system. Consequently, while DisplayPort transmits the EOTF identifier within the SDP to switch the display mode, it does not require mastering display or content light level metadata payloads, simplifying the transmission pipeline.

Handshake and Capability Discovery (EDID and DisplayID)

Before HDR transmission begins, the source and sink negotiate supported EOTF curves through the DisplayPort Auxiliary (AUX) channel.

The display provides its capabilities to the source via Extended Display Identification Data (EDID) and modern DisplayID 2.0 structures. Within the CTA-861 extension block of the EDID, the HDR Static Metadata Data Block lists the specific EOTF curves the display panel can decode.

If the display declares support for Byte 3, Bit 2 (SMPTE ST 2084) or Bit 3 (HLG), the source graphics driver unlocks the respective HDR signaling mode. The driver then maps the operating system or application color space to the appropriate pixel format, tags the Secondary Data Packets with the matching EOTF flags, and streams the content over the main link lanes.
