DisplayPort Color Range: Crushed Shadows and Washed Blacks

A misconfigured color range over DisplayPort occurs when the graphics processing unit (GPU) and the monitor disagree on how brightness levels are mapped across the digital spectrum. In digital video, luminance values are represented along a scale—typically Full RGB (0–255) or Limited RGB (16–235). When the GPU and monitor operate on mismatched standards, the signal is improperly expanded or compressed. This discrepancy results in either "black crush," where dark gradients collapse into solid black, or elevated black levels, where deep blacks appear as a washed-out, milky gray.

The Difference Between Full and Limited RGB

In standard 8-bit color, there are 256 possible values per color channel (Red, Green, and Blue).

  • Full Range (0–255): Standard for PC monitors. Pure black is defined as value 0, and peak white is value 255. All 256 values are utilized to render fine gradients, subtle shadow details, and specular highlights.
  • Limited Range (16–235): Historically developed for broadcast television and legacy consumer electronics to prevent signal degradation. Pure black is anchored at 16, and peak white is anchored at 235. Values from 0–15 are reserved as "footroom" (blacker-than-black), and values 236–255 are reserved as "headroom" (whiter-than-white).

DisplayPort natively defaults to the Full RGB standard because it was engineered specifically for computing environments. However, driver bugs, faulty EDID (Extended Display Identification Data) communication, or custom display profiles can cause the GPU or display to default to Limited RGB.

Scenario 1: GPU Outputs Limited, Monitor Expects Full (Washed-Out Blacks)

If the GPU outputs a Limited signal (16–235) while the monitor is set to receive a Full signal (0–255), the contrast profile breaks down into a washed-out haze.

The monitor expects the darkest possible signal to arrive at code value 0. Because the GPU is outputting Limited range, the darkest signal it transmits is value 16. The monitor interprets value 16 as dark gray rather than absolute black. At the same time, the brightest value sent by the GPU is 235, which the monitor displays as an off-white rather than true white (255).

The dynamic range is artificially compressed into the center of the spectrum. Contrast ratio drops significantly, shadows lack depth, and the entire desktop, game, or video looks foggy and flat.

Scenario 2: GPU Outputs Full, Monitor Expects Limited (Black Crush)

The opposite problem occurs when the GPU outputs a Full signal (0–255), but the monitor is configured to expect a Limited signal (16–235). This produces severe black crush and blown-out highlights.

Because the monitor's processing pipeline treats value 16 as the absolute black threshold, it clips every incoming signal between 0 and 16 into uniform, pitch-black pixels. Any subtle gradations in shadows—such as textures in dark clothing, night-time geometry in games, or dark hair in portraits—are erased. Similarly, because the monitor treats value 235 as maximum white, all values between 236 and 255 clip into solid white, eliminating highlight detail.

Diagnosing and Resolving Color Range Mismatches

To restore correct dynamic range and color accuracy, both the GPU driver settings and the monitor's internal firmware must match. For PC use, both should be set to Full RGB (0–255).

  • NVIDIA: Open NVIDIA Control Panel > Display > Change resolution. Under "Apply the following settings," select Use NVIDIA color settings, and set Output dynamic range to Full.
  • AMD: Open AMD Software: Adrenalin Edition > Gaming > Display. Locate Pixel Format and ensure it is set to RGB 4:4:4 Pixel Format PC Standard (Full RGB).
  • Monitor OSD: Access the physical On-Screen Display (OSD) menu of the monitor. Check settings labeled Black Level, HDMI/DP RGB Range, or Color Format, and ensure it is set to Full, Normal, or PC rather than Limited or Low.
