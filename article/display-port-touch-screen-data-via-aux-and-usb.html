DisplayPort Touch-Screen Data via AUX and USB

This article explores how interactive displays transmit touch-screen input data back to host computers using DisplayPort technology. While DisplayPort primarily functions as a high-bandwidth downstream video interface, returning touch data upstream requires dedicated communication pathways. The following sections explain the mechanics of achieving this return path natively through the DisplayPort Auxiliary (AUX) channel and practically via embedded USB integration.

The Upstream Data Challenge

Standard DisplayPort interfaces are asymmetric, designed to push massive amounts of downstream video and audio data from the graphics processing unit (Source) to the monitor (Sink). Touch screens, digitizers, and interactive displays require a bidirectional or reverse communication channel—an upstream return path—to transmit coordinates, pressure levels, and gesture data back to the operating system's Human Interface Device (HID) drivers.

The DisplayPort AUX Channel Return Path

The DisplayPort specification includes the Auxiliary (AUX) Channel, a dedicated bidirectional, half-duplex sideband link. While predominantly utilized for link management, configuration data (DPCD), Extended Display Identification Data (EDID), and HDCP handshakes, it can also function as a low-bandwidth data conduit.

Standard AUX vs. Fast AUX

  • Standard AUX: Operates at 1 Mbps using Manchester-II encoding. It is optimized for small, bursty configuration commands. Although theoretically capable of handling low-polling-rate touch data, it offers very limited bandwidth and faces latency bottlenecks when video link maintenance occurs simultaneously.
  • Fast AUX (eDP): Primarily specified within Embedded DisplayPort (eDP) for internal integrations like laptops, tablets, and all-in-one systems. Fast AUX raises the sideband speed up to 720 Mbps. This provides adequate headroom to encapsulate HID-over-AUX or standard I2C/SPI touch-controller packets alongside standard display parameters.

Native HID Tunneling

When utilizing the AUX channel directly, touch data packets are encapsulated within DPCD registers or tunneled using vendor-defined protocols. The host system's GPU driver reads these registers during polling intervals or responds to an interrupt signal (HPD pulse) triggered by the display sink. Due to driver complexity and fragmentation across GPU vendors, using the external AUX channel for generic touch inputs remains rare outside of tightly controlled, embedded ecosystems.

The Embedded USB Return Path

In modern commercial, industrial, and consumer displays, touch return paths are overwhelmingly implemented using USB signals integrated alongside the DisplayPort data stream.

DisplayPort Alternate Mode over USB Type-C

The most common implementation of an integrated DisplayPort touch return path is DisplayPort Alternate Mode (DP Alt Mode) over USB-C. Rather than modifying the DisplayPort protocol itself, the physical connection isolates video and input traffic across separate pins within the same cable:

  • High-Speed Display Data: Configurable high-speed differential lanes carry native DisplayPort A/V data downstream. A connection can utilize either two lanes (allowing simultaneous SuperSpeed USB 3.x) or all four lanes (maximizing video resolution and refresh rates).
  • Dedicated USB Return Path: The USB-C connector maintains dedicated pins for USB 2.0 (D+/D-) regardless of the DP lane allocation. The touch-screen digitizer connects internally as an onboard USB HID controller. Touch coordinates are sent directly upstream over these USB 2.0 lines to the host system.

Embedded USB Hubs in Standard DisplayPort Displays

For displays using standard physical DisplayPort connectors, the DisplayPort stream cannot carry standard USB traffic natively. In these setups, touch functionality requires one of two configurations:

  1. Dual-Cable Architecture: A standard DisplayPort cable handles downstream video, while a separate USB Type-B or Type-C upstream cable connects the monitor’s internal touch digitizer to the host PC.
  2. KVM/Tethered Cabling: Specialized industrial cables integrate standard DisplayPort wiring and USB data lines into a single jacket, breaking out at the host side into separate DisplayPort and USB connectors.

Summary of Implementation Trade-Offs

  • AUX/eDP Implementation: Eliminates secondary interfaces and optimizes component count, making it ideal for internal device engineering. However, it requires proprietary driver support and is constrained by strict protocol overhead.
  • USB-C / DP Alt Mode Implementation: The current industry standard for external peripherals. It fully segregates video bandwidth from input polling, relies on universal native OS HID drivers, and delivers minimal latency for real-time touch, pen, and multi-gesture recognition.
