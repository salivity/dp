Panel Replay vs Panel Self Refresh in DisplayPort

Panel Replay is a modern display power-saving technology designed by VESA to supersede legacy Panel Self Refresh (PSR and PSR2) across internal and external DisplayPort interfaces. While both technologies reduce system power consumption by allowing a display to refresh static content from an integrated local memory buffer rather than continually receiving data from the GPU, Panel Replay significantly refines this process. It achieves higher efficiency by introducing faster wake times, fine-grained selective updating, native compatibility with Variable Refresh Rate (VRR), and support for standard external DisplayPort connections beyond traditional embedded panels.

The Foundation and Limitations of Legacy PSR

Panel Self Refresh was originally conceived for embedded DisplayPort (eDP) systems, primarily laptops, to extend battery life. In standard PSR (PSR1), when the on-screen image becomes static, the GPU signals the display's timing controller (TCON) to store the current frame in a Remote Frame Buffer (RFB). The main display link then enters a low-power sleep state while the TCON continuously reads from its local memory to refresh the panel.

PSR2 improved on this by adding Selective Update (SU), enabling the system to transmit only the scanlines or partial blocks that changed rather than the entire frame. However, legacy PSR implementations suffer from several notable drawbacks:

  • High Entry/Exit Latency: Waking the main link from sleep requires link training and resynchronization, introducing measurable latency and potential visual stutter.
  • Limited Scope: PSR was engineered specifically for embedded displays (eDP) and did not translate well to external monitors.
  • Friction with Modern Gaming Features: Legacy PSR often conflicts with Adaptive-Sync or Variable Refresh Rate (VRR) because its rigid timing mechanisms assume fixed refresh cycles.

How Panel Replay Improves Upon Panel Self Refresh

Panel Replay, introduced alongside the eDP 1.5 and DisplayPort 2.0/2.1 standards, redesigns how the GPU and display coordinate frame storage and transmission. It addresses legacy PSR's shortcomings through several architectural advancements:

1. Native Support for External DisplayPort Devices

Unlike legacy PSR, which was predominantly locked to internal eDP laptop screens, Panel Replay is built into standard DisplayPort specifications. This allows standalone desktop monitors, docking stations, and multi-display setups using Multi-Stream Transport (MST) to use self-refresh power-saving states without breaking display compliance or link stability.

2. Seamless Integration with Adaptive-Sync and VRR

Panel Replay is designed from the ground up to coexist with Variable Refresh Rate (Adaptive-Sync/G-Sync/FreeSync). Instead of requiring a fixed panel refresh rate to sustain the local image, Panel Replay allows the display to adjust its internal refresh timings dynamically while drawing from the local buffer. This prevents frame-pacing issues and eliminates the stutter often seen when legacy PSR monitors wake up during variable frame rate scenarios.

3. Reduced Link Retraining Latency

A primary bottleneck of legacy PSR is the delay required to re-establish the main link when returning from a low-power state. Panel Replay streamlines the physical layer handshake, often using optimized fast-wake sequences (such as ALPM, or Advanced Link Power Management). The main link can re-engage in a fraction of the time legacy PSR requires, making the transition completely invisible to the user and responsive enough for high-speed input environments.

4. Finer-Grained Selective Updates

While PSR2 introduced selective updates, it relied on line-based or coarse block-based coordinates that still led to redundant data transfer. Panel Replay utilizes more precise packet-based region updating. If a small element on the screen changes—such as a blinking text cursor, a system tray clock, or a small video playback window—only the exact pixel clusters for that region are transmitted. The rest of the panel remains powered down or continues to replay existing buffer data, maximizing link-off duration.

5. Scalability for Ultra-High Bit Rate (UHBR) Modes

As displays push to 4K, 8K, and high refresh rates (144Hz and above), transmitting uncompressed or even DSC (Display Stream Compression) data demands massive bandwidth. Panel Replay handles high pixel rates and compressed streams more effectively than legacy PSR, allowing modern gaming and professional monitors to conserve power and reduce thermal output without lowering visual fidelity.
