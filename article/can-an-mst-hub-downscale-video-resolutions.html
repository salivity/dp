Can an MST Hub Downscale Video Resolutions?

DisplayPort Multi-Stream Transport (MST) hubs cannot downscale video resolutions locally because they lack integrated video scaler hardware. Instead, the host Graphics Processing Unit (GPU) is fully responsible for rendering, scaling, and outputting each independent display stream at its designated resolution over the DisplayPort link. This guide clarifies how MST technology processes video data and explains the host system's role in multi-monitor bandwidth management.

How DisplayPort MST Hubs Process Signals

An MST hub functions primarily as a protocol-aware packet router rather than a video processing unit. Under the DisplayPort 1.2 (and later) specifications, the host GPU multiplexes multiple independent video streams into a single physical link via Time Division Multiplexing (TDM).

When these multiplexed data packets reach the MST hub, the device reads the Stream ID tags embedded in the DisplayPort transport packets. The hub’s internal routing logic directs each packet to the designated physical output port (such as DisplayPort, HDMI, or USB-C). Because the hub operates strictly at the transport and link layers, it does not decode pixels into a frame buffer, process spatial scaling algorithms, or re-encode video frames to lower resolutions.

The Role of the Host GPU

All video scaling happens directly on the host GPU before data transmission:

  • Native Rendering: The GPU queries the Extended Display Identification Data (EDID) or DisplayID from each connected monitor through the MST hub's auxiliary (AUX) channels. If a display runs at 1080p, the GPU outputs a native 1080p stream.
  • GPU-Side Downscaling: If you set a 4K desktop resolution on a 1080p monitor (such as via supersampling or dynamic super resolution), the GPU renders at 4K, downscales the image to 1080p internally, and then transmits the final 1080p stream over the wire.
  • Independent Timings: The GPU must have sufficient display engines (display pipelines) to generate the distinct pixel clocks, timings, and resolutions required by each screen.

Bandwidth and Display Stream Compression (DSC)

Because the hub cannot downscale video to save bandwidth, the total combined bandwidth of all streams rendered by the GPU cannot exceed the physical bandwidth limit of the single DisplayPort connection running to the hub.

Some modern DisplayPort 1.4 and 2.1 MST hubs feature integrated Display Stream Compression (DSC) decoders. In these setups, the host GPU visually compresses high-resolution streams before sending them to the hub, and the hub decompresses the video streams before passing them to the monitors. However, decompression is not downscaling; the stream retains its original target resolution and pixel dimensions.

Summary

Standard DisplayPort MST hubs cannot alter, downsample, or downscale the resolution of a video stream locally. Any adjustment to display resolution, refresh rate, or image scaling must be handled entirely by the host GPU before the video packets are multiplexed across the cable.
