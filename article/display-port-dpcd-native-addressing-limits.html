DisplayPort DPCD Native Addressing Limits

The DisplayPort Configuration Data (DPCD) space is a standardized memory map used by DisplayPort source and sink devices to negotiate capabilities, configure communication links, and monitor connection status. This article provides a direct overview of the DPCD architecture, detailing its native addressing limit, the communication mechanics governed by the Auxiliary Channel (AUX CH), and how this address boundary is allocated across the DisplayPort specification.

The native addressing limit of the DisplayPort Configuration Data (DPCD) space is 1 Megabyte (1 MB), corresponding to a total capacity of 1,048,576 bytes. This limit is defined by a 20-bit physical address space, spanning hexadecimal addresses from 0x00000 to 0xFFFFF.

The Role of the AUX Channel in Addressing

DPCD registers are read and written using the DisplayPort Auxiliary Channel (AUX CH), a dedicated sideband communication bus. In a native AUX transaction header, the protocol allocates exactly 20 bits for the target register address (\(A[19:0]\)). Because the native AUX request structure cannot accommodate an address value greater than 20 bits without protocol modification, the maximum addressable boundary for native DPCD access remains capped at 1 MB.

Native AUX read and write operations allow burst access ranging from 1 to 16 bytes per single transaction, operating directly within this 20-bit address range.

Structure of the 1 MB DPCD Address Space

Although the architecture provides 1 MB of addressable space, standard DisplayPort operations primarily utilize specific ranges, leaving extensive room for future revisions and vendor-specific features:

  • 0x00000 – 0x000FF (Receiver Capability Field): Defines the sink device's native capabilities, including supported data rates, lane counts, Enhanced Framing support, and Downstream Port configurations.
  • 0x00100 – 0x001FF (Link Configuration Field): Used by the source to set the active transmission parameters, such as targeted lane count, link rate, spread-spectrum clocking, and training patterns.
  • 0x00200 – 0x002FF (Link / Sink Status Field): Updated by the sink during link training and active transmission to report clock recovery, channel equalization, symbol lock status, and inter-lane alignment.
  • 0x00300 – 0x005FF (Source / Sink Specific Fields): Dedicated to source-specific configuration, branch device discovery, and sideband messaging support.
  • 0x00600 – 0x006FF (Driver and Power Management): Controls device power states (D0 active, D3 power-down), branch settings, and display sleep behavior.
  • 0x02200 – 0x022FF and Higher: Designated for extended receiver capabilities introduced in newer versions (such as DisplayPort 1.4 and DisplayPort 2.1), including Display Stream Compression (DSC), Forward Error Correction (FEC), and UHBR transmission modes.
  • 0x80000 – 0xFFFFF: Typically designated for vendor-specific implementations, extended authentication protocols, and test automation fixtures.

By utilizing a 20-bit address scheme, the DisplayPort standard ensures that low-bandwidth link management commands can easily scale to support modern high-bandwidth features without exhausting the native DPCD memory map.
